# Подбор кандидатов — Как это работает

---

## Способ 1: Живой поиск через HH.uz

```
Вакансия готова
        │
        ▼
ИИ генерирует 6 поисковых запросов
(например: "Python Developer", "Backend Engineer",
"Питон разработчик", "Бэкенд программист")
        │
        ▼
Поиск на HH.uz по каждому запросу
(макс. 2000 резюме — 40 страниц × 50 штук)
        │
        ▼
Предварительная фильтрация резюме по заголовку
(есть ли совпадающие слова с названием вакансии?)
        │
        ▼
Подходящие отправляются на оценку ИИ
(Ollama: выставляет оценку от 0 до 100)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ 60
(топ 10 записываются в MongoDB)
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда нужны актуальные, свежие, активные кандидаты.

---

## Способ 2: Поиск через Qdrant Talent Pool

Этот способ состоит из **двух этапов**:

### Этап 1 — Выполняется один раз: Заполнение пула (Ingestion)

```
Нажимается кнопка "Ingest"
        │
        ▼
С HH.uz загружается 2000 резюме
по Узбекистану
        │
        ▼
Каждое резюме преобразуется в текст
(должность + навыки + опыт)
        │
        ▼
Ollama создаёт вектор из 768 чисел
для каждого текста
(представление смысла в числовом виде)
        │
        ▼
Векторы сохраняются в Qdrant
(один раз — можно использовать постоянно)
```

### Этап 2 — Выполняется каждый раз: Поиск

```
Вакансия готова
        │
        ▼
Вакансия преобразуется в текст,
Ollama строит её вектор
        │
        ▼
Qdrant: находит 50 наиболее похожих
кандидатов по вектору вакансии
(cosine similarity ≥ 0.5)
        │
        ▼
Топ 30 отправляются на оценку ИИ
(Ollama: выставляет оценку от 0 до 100)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ 60
(топ 10 записываются в MongoDB)
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда важна скорость и пул уже заполнен.

---

## Сравнение двух способов

| | Способ 1 (Поиск HH) | Способ 2 (Qdrant Pool) |
|---|---|---|
| **Актуальность** | Свежие данные с HH при каждом поиске | Данные на момент заполнения пула |
| **Скорость** | Медленнее (HH API + AI scoring) | Быстрее (векторный поиск быстрый) |
| **Подготовка** | Не нужна — работает напрямую | Требуется предварительное заполнение пула |
| **Охват** | Ищет по ключевым словам вакансии | Выбирает из всех 2000 кандидатов |
| **Соответствие** | Для любой вакансии | Только среди кандидатов в пуле |

## Подбор через загрузку файла (Способ 3)

```
Загружается файл PDF или DOCX
        │
        ▼
Текст извлекается из файла
        │
        ▼
ИИ: извлекает имя, должность, навыки, зарплату
        │
        ▼
ИИ: оценивает соответствие вакансии в процентах
        │
        ▼
Сохраняется как кандидат
```

**Когда использовать:** Когда нужно проверить одного конкретного кандидата.
