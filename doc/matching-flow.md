# Подбор кандидатов — Как это работает

---

## Способ 1: Живой поиск через HH.uz

```
Вакансия готова
        │
        ▼
ИИ генерирует 6 поисковых запросов
(например: "Python Developer", "Backend Engineer",
"Питон разработчик", "Бэкенд программист")
        │
        ▼
Поиск на HH.uz по каждому запросу
(макс. 2000 резюме — 40 страниц × 50 штук)
        │
        ▼
Предварительная фильтрация резюме по заголовку
(есть ли совпадающие слова с названием вакансии?)
        │
        ▼
Подходящие отправляются на оценку ИИ
(Ollama: выставляет оценку от 0 до 100)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ 60
(топ 10 записываются в MongoDB)
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда нужны актуальные, свежие, активные кандидаты.
**Кнопка в UI:** Smart Rematch

## Способ 2: Поиск через Qdrant Talent Pool

Этот способ состоит из **двух этапов**:

### Этап 1 — Выполняется один раз: Заполнение пула (Ingestion)

```
Нажимается кнопка "Ingest"
        │
        ▼
С HH.uz загружается 2000 резюме
по Узбекистану
        │
        ▼
Каждое резюме преобразуется в текст
(должность + навыки + опыт)
        │
        ▼
Ollama создаёт вектор из 768 чисел
для каждого текста
(представление смысла в числовом виде)
        │
        ▼
Векторы сохраняются в Qdrant
(один раз — можно использовать постоянно)
```

### Этап 2 — Выполняется каждый раз: Поиск

```
Вакансия готова
        │
        ▼
Вакансия преобразуется в текст,
Ollama строит её вектор
        │
        ▼
Qdrant: находит 50 наиболее похожих
кандидатов по вектору вакансии
(cosine similarity ≥ 0.5)
        │
        ▼
Топ 30 отправляются на оценку ИИ
(Ollama: выставляет оценку от 0 до 100)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ 60
(топ 10 записываются в MongoDB)
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда важна скорость и пул уже заполнен.
**Кнопка в UI:** Talent Pool

## Способ 3: Подбор через загрузку файла

```
Загружается файл PDF или DOCX
        │
        ▼
Текст извлекается из файла
        │
        ▼
ИИ: извлекает имя, должность, навыки, зарплату
        │
        ▼
ИИ: оценивает соответствие вакансии в процентах
        │
        ▼
Сохраняется как кандидат
```

**Когда использовать:** Когда нужно проверить одного конкретного кандидата.
**Кнопка в UI:** Match from File

## Способ 4: Live Pool — Живой векторный поиск (без предварительного заполнения)

Этот способ объединяет живой сбор данных с HH.uz и временное векторное хранилище.
Подготовка не нужна — всё происходит в рамках одного запроса.

```
Вакансия готова
        │
        ▼
ИИ извлекает список навыков из описания вакансии
(Ollama: extract_fields → список skills)
        │
        ▼
Навыки преобразуются в вектор запроса
(Ollama embed → 768 чисел)
        │
        ▼
Создаётся временная коллекция в Qdrant
(имя: tmp_{vacancy_id})
        │
        ▼
С HH.uz загружается 2000 резюме по Узбекистану
(20 страниц × 100 штук, параллельно)
        │
        ▼
Каждое резюме встраивается в вектор
(Ollama embed_batch, пакетами по 50)
        │
        ▼
Все векторы загружаются во временную коллекцию Qdrant
        │
        ▼
Qdrant: cosine similarity поиск по вектору вакансии
(порог ≥ 0.85 — строже, чем Способ 2)
→ топ 50 совпадений
        │
        ▼
Топ 30 отправляются на оценку ИИ
(Ollama: выставляет оценку от 0 до 100)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ 60
(топ 10 записываются в MongoDB)
        │
        ▼
Временная коллекция Qdrant удаляется
(очистка — данные не сохраняются в Qdrant)
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда нужны свежие кандидаты с высокой точностью совпадения,
и нет времени на предварительное заполнение постоянного пула.
**Кнопка в UI:** Live Pool

### Ключевые отличия от Способа 2

| | Способ 2 (Talent Pool) | Способ 4 (Live Pool) |
|---|---|---|
| **Подготовка** | Нужна предварительная инъекция | Не нужна |
| **Данные** | Из постоянного пула (могут устареть) | Свежие с HH.uz каждый раз |
| **Порог сходства** | ≥ 0.5 (мягче) | ≥ 0.85 (строже) |
| **Хранение в Qdrant** | Постоянная коллекция | Временная, удаляется после |
| **Скорость** | Быстрее (пул уже есть) | Медленнее (сбор + индексация) |
| **Точность** | Стандартная | Выше (строгий порог + свежие данные) |

## Способ 5: Поиск по базе данных (DB Match) — с Qdrant pre-filter

Этот способ оценивает кандидатов, уже загруженных в MongoDB (через файл, XLSX или HH),
и применяет **векторную фильтрацию через Qdrant** перед LLM-оценкой, чтобы не тратить
время на нерелевантных кандидатов.

```
Вакансия готова
        │
        ▼
Все кандидаты из MongoDB извлекаются
(xlsx-группы + file/hh-кандидаты, без дубликатов)
        │
        ▼
Текст каждого кандидата строится
(должность + навыки)
        │
        ▼
Ollama embed_batch: все тексты встраиваются в вектора
(параллельно, concurrency=8 — быстро)
        │
        ▼
Создаётся временная коллекция Qdrant: "db_match_{vacancy_id}"
Все векторы загружаются туда
        │
        ▼
Вакансия встраивается в вектор (Ollama embed)
Qdrant: cosine similarity → топ 25 кандидатов
(весь поиск — миллисекунды)
        │
        ▼
Только топ 25 отправляются на оценку ИИ
(Ollama: score_candidate, 10 параллельных вызовов через asyncio.gather)
        │
        ▼
Сохраняются кандидаты с оценкой ≥ min_score
Устаревшие записи удаляются
        │
        ▼
Временная коллекция Qdrant удаляется
        │
        ▼
Результат: кандидаты отображаются на странице вакансии
```

**Когда использовать:** Когда кандидаты уже загружены в базу (XLSX-списки, загруженные PDF, импорт с HH).
**Кнопка в UI:** Match from DB

### Оптимизация производительности (реализовано)

| Шаг | До оптимизации | После оптимизации |
|---|---|---|
| **Количество LLM-вызовов** | N (все кандидаты) | 25 (только топ Qdrant) |
| **Порядок выполнения** | Последовательный | Параллельный (`asyncio.gather`) |
| **100 кандидатов** | ~500 сек | ~15–20 сек |
| **httpx соединения** | Новое TCP на каждый вызов | Persistent connection pool |

## Сравнение всех пяти способов

| | Способ 1 (Smart Rematch) | Способ 2 (Talent Pool) | Способ 3 (File Upload) | Способ 4 (Live Pool) | Способ 5 (DB Match) |
|---|---|---|---|---|---|
| **Актуальность** | Свежие данные с HH | Данные на момент инъекции | Один конкретный кандидат | Свежие данные с HH | Ранее загруженные |
| **Скорость** | Медленнее | Быстрее | Мгновенно | Медленнее | Быстро (Qdrant pre-filter) |
| **Подготовка** | Не нужна | Нужна инъекция | Не нужна | Не нужна | Нужна загрузка кандидатов |
| **Охват** | По ключевым словам | Все 2000 в пуле | 1 файл | Все 2000 свежих | Все в MongoDB |
| **Точность** | Высокая (AI scoring) | Стандартная (≥ 0.5) | Высокая | Очень высокая (≥ 0.85) | Высокая (Qdrant + AI) |
| **Хранение** | MongoDB | MongoDB + Qdrant (постоянно) | MongoDB | MongoDB (Qdrant временно) | MongoDB (Qdrant временно) |
